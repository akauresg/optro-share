TPRM stage timeout UX

A quick sketch of how an expired assessment stage could feel. Same pattern across surfaces: neutral "Paused" framing, recovery actions inline, in-progress work preserved.

Surface 1 — Vendor queue (list view)

Scannable, no shame

Neutral "Paused" pill so expired workflows don't shout in a long list. The amber tone is reserved for "Due soon" — the 80% warning, which is when the user can still save the workflow.

Escalation cadence

The hard timeout should rarely fire

Two warnings before the cutoff. If they land, the expired state stays a tail case rather than the user's first encounter with the system "punishing" them.

~50%
In-app banner only. "Heads up: no activity in 45 days."
~80%
"Due soon" pill + email to owner and TPRM admin.
100%
"Paused" pill + banner. Recovery actions exposed. Work preserved.
